## 2. The 5-Stage Engineering Pipeline

### Stage 1: Mathematical & Physical Formulation (Human)
Before writing any code, I formulate the underlying domain problem:
* Deriving differential equations and coordinate transformations ($\text{Perifocal} \to \text{ECI} \to \text{ECEF} \to \text{Three.js}$).
* Establishing grammatical precedence rules and token hierarchies for Computer Algebra Systems (CAS).
* Defining numerical stability criteria (Courant CFL condition $S \le 1/\sqrt{2}$).
* Imposing strict latency and memory budgets ($60\text{ FPS}$, $<50\text{ MB}$ memory footprint).

### Stage 2: Systems Architecture & Interface Contracts (Human)
I structure the system boundaries, data contracts, and memory topologies:
* Specifying contiguous `Float32Array` buffers for WebGL GPU instancing to prevent draw-call saturation.
* Designing immutable Abstract Syntax Tree (AST) node structures for recursive pattern-matching.
* Establishing asynchronous task queues and retry backoff policies for media pipelines.

### Stage 3: Agentic Synthesis & Boilerplate Acceleration (AI)
I direct AI tools to accelerate implementation:
* Generating typed API wrappers, shader boilerplate, and standard CSS grid styling.
* Scaffolding test harnesses and synthetic test-case generators.
* Translating structured mathematical matrices into WebGL uniform bindings.

### Stage 4: Empirical Audit, Profiling & Boundary Probing (Human)
I subject all generated code to rigorous empirical validation:
* Profiling frame execution times, garbage collection spikes, and heap allocations via Chrome DevTools.
* Auditing telemetry against live NORAD ephemeris records.
* Stress-testing CAS parsers against non-elementary integrals and invalid mathematical inputs.

### Stage 5: Final Accountability & Interview Defense (Human)
I take complete ownership of the engineering result:
* Fully understanding why each algorithm and data structure was selected.
* Explaining exact failure boundaries and physical simplifications made.
* Defending every design decision in technical admissions interviews.

## 4. Case Studies in Practice

### Case Study A: Orbital Command (3D WebGL Engine)
* **Human Architectural Choice:** Recognized that rendering 10,000 individual Three.js meshes causes CPU draw-call bottlenecks. Directed the AI to restructure rendering into an `InstancedMesh` with a flattened contiguous `Float32Array` matrix buffer.
* **Empirical Benchmark:** 10,240 satellites rendered at 58–60 FPS sustained on Chrome WebGL2 ($~14.8\text{ ms/frame}$ latency, $<0.8\text{ ms}$ spatial raycast lookup).

### Case Study B: Math Logic Engine (Symbolic CAS)
* **Human Mathematical Choice:** Formulated recursive descent grammar and LIATE integration heuristics for competitive engineering calculus. Directed the AI to implement AST visitor traversal and Streamlit UI explorer.
* **Empirical Benchmark:** 94.2% exact match across 120 standard JEE/EJU integral benchmarks, with explicit boundary warnings on Liouville non-elementary classes ($\int e^{-x^2} dx$).

### Case Study C: Quantum Wave Simulation Suite (Wave Mechanics)
* **Human Physical Choice:** Derived 2D scalar wave equations, CFL stability limit ($S = c\Delta t/\Delta x = 0.50$), and Born probability accumulator. Directed the AI to optimize HTML5 Canvas 2D image buffer manipulation.
* **Empirical Benchmark:** 40,000 spatial cells stepped at 60 FPS, with 5,000 Monte-Carlo particle hits converging to Fresnel-Kirchhoff interference curves ($R^2 > 0.98$).
